# Marketing AI Agent — 개발 기획서

> 기준: `docs/reference/track-2-marketing-agent.pdf` (TRACK 2, 7쪽)  
> 상태: 구현 결과와 검증 상태는 `docs/results/`에서 별도 관리  
> 환경: Windows 11 로컬 · Codex · Ollama `qwen3.5:4b`

## 1. 목표

지정된 YouTube 채널의 영상을 불러오고, 영상 맥락에 맞는 **운명원 연애 사주 관련 댓글**을 생성한 뒤, Chrome 프로필을 통해 **한 글자씩 입력 → 게시 → 내 댓글 확인**까지 수행하는 로컬 대시보드를 개발한다.

기본 사용자 흐름: **① 영상 불러오기 → ② 영상 선택·AI 고민 요약/댓글 확인 → ③ 댓글 달기(Chrome 실행·입력·게시·확인)**. 별도 승인 단계를 추가해 과제의 3단계 흐름을 변경하지 않는다. 게시 전 댓글 편집은 지원한다.

## 2. 과제 요구사항

### 2.1 필수 — 우선 구현

| ID | 요구 | 완료 판정 |
|---|---|---|
| F1 | 지정 채널 5개의 최신 영상 조회 | `영상 불러오기` 한 번으로 썸네일·제목·채널·업로드 날짜 표시 |
| F2 | 영상 선택 및 분석 | 선택 시 영상 속 연애 고민 한 줄과 댓글 초안 표시 |
| F3 | 맥락 기반 생성 | 자막(없으면 제목·설명)과 인기 댓글을 활용하고, 실제 확인 가능한 구체적 장면·발언 1개 이상 반영 |
| F4 | 댓글 제약 | 40~120자, 영상별 차별화, `운명원` 언급, 링크·해시태그·허위 직접 이용 후기 금지 |
| F5 | Chrome 프로필 1개 | 로그인된 `유튜브1` 프로필을 지정된 프로필 경로로 실행 |
| F6 | 실제 댓글 자동 게시 | 한국어 YouTube에서 입력창 → 글자별 타이핑 → 게시 클릭 → 내 댓글 표시 확인을 화면에 노출 |
| F7 | 상태·오류 | 프로필 여는 중/입력 중/게시 완료·댓글 보기 상태 표시, 실패 원인과 화면 캡처 저장 |
| F8 | 게시 제한 | 허용된 5개 채널+본인 테스트 영상만 게시, 영상당 댓글 1개, 하루 기본 10개 |
| F9 | 이력 | 어느 영상·프로필·댓글·성공/실패인지 시간순 확인 |
| F10 | 제출 | 2~3분 실제 시연 영상(필수), 제작 의도, Git 저장소(선택) |

### 2.2 가점 — 필수 검증 이후 구현

| ID | 가점 | 구현 범위 |
|---|---|---|
| B1 | `유튜브1~3` 프로필 선택 **또는** 자동 배정 | 프로필 선택을 우선 구현. 자동 순환은 필수가 아님 |
| B2 | 영상 URL 직접 입력 | 영상 ID와 실제 채널 ID를 조회하여 게시 허용 여부 검증 |
| B3 | 새 영상 AI 초안 즉석 생성 | 입력·신규 선택 영상으로 분석·초안 다시 생성 |
| B4 | 뜨기 직전 영상 탐색 | `연애` 키워드, 조회수 1,000~5,000, 시간당 조회수 150 이상 후보 탐색. **초안까지만** 제공 |

가점은 선택 항목이므로 미구현 시 필수 기능 완료와 구분한다. B4 후보 영상은 게시 허용 목록에 자동 추가하지 않는다. 조회수 측정 기준과 데이터 시차를 화면에 표시한다.

## 3. 기술 스택

| 영역 | 선택 | 역할 |
|---|---|---|
| Frontend | React + TypeScript + Vite | 로컬 대시보드 |
| Backend | Python + FastAPI | YouTube·AI·브라우저 작업 및 규칙 검증 |
| AI | Ollama `qwen3.5:4b` | 연애 고민 분석·댓글 초안 생성. 품질은 실영상으로 검증 |
| 영상 | YouTube Data API v3 | 목록·메타데이터·공개 댓글·채널 확인 |
| Browser | Playwright Python + Chrome | Persistent Context, 가시적 타이핑·게시·확인 |
| DB | SQLite | 게시 제한·분석·초안·실행 이력 |
| E2E | Playwright Test + 실제 Chrome 게시 흐름 검증 | 화면·서버 연계 및 본인 테스트 영상 게시 확인 |
| 설정 | `.env` | API 키·프로필 경로·모델·한도 |

OpenAI API, 임베딩, RAG, Redis, PostgreSQL, Celery, MCP, Multi-Agent는 **애플리케이션 필수 구성에 포함하지 않는다**. Playwright MCP는 Codex의 개발·디버깅 도구일 뿐 앱의 실행 의존성이 아니다. 모델 교체는 실제 영상 품질 비교 후 결정한다.

### 설정 초안

```dotenv
YOUTUBE_API_KEY=
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen3.5:4b
DATABASE_URL=sqlite:///./data/marketing-agent.db
CHROME_USER_DATA_DIR=./local/chrome-profiles/youtube1
DAILY_MAX_COMMENTS=10
COMMENT_MIN_CHARS=40
COMMENT_MAX_CHARS=120
TEST_VIDEO_IDS=
```

프로필 2·3은 가점 구현 시 설정을 확장한다. 평소 사용하는 기본 Chrome 프로필은 자동 제어하지 않으며, `유튜브1`의 지정 프로필 경로를 사용한다.

사용자 추가 요청: 환경 설정에서 유튜브2·3 등록 및 게시 프로필 선택. 기존 유튜브1 경로 유지,
추가 프로필의 별도 폴더·일반 Chrome 로그인·SQLite 등록 목록 저장. 자동 계정 순환 제외.

## 4. 기능 흐름과 구현 기준

```mermaid
flowchart TD
    A[① 지정 채널 영상 불러오기] --> B[② 영상 선택]
    B --> C[자막·제목·설명·인기 댓글 수집]
    C --> D[Ollama 고민 요약·댓글 생성]
    D --> E[댓글 확인·필요 시 편집]
    E --> F{서버 게시 제한 재검증}
    F -->|통과| G[③ Chrome 프로필 실행]
    F -->|차단| X[사유 기록]
    G --> H[영상 열기·한 글자씩 입력]
    H --> I[댓글 게시]
    I --> J[게시된 댓글 확인]
    J --> K[(SQLite 이력·상태)]
```

**수집·생성**

- 채널별 최신 영상 목록과 선택 영상의 제목·설명·공개 인기 댓글을 조회한다.
- 공개 자막 우선 수집, 미확보 시 영상 20%·50%·80%의 3장면·제목·설명·인기 댓글 활용. 장면·발언 창작 금지. 음성 수집·전사 제외. 설명·근거 더보기 제거.
- 입력에 없는 장면·대사를 지어내지 않는다. 자막이 없으면 제목·설명과 인기 댓글을 활용하며, 실제로 확인한 자료 유형을 기록한다. 캡처 3장은 전체 영상 분석을 의미하지 않는다.
- LLM은 고민 한 문장, 근거·출처, 댓글 초안을 구조화해 반환한다. 길이·금지 표현·운영 규칙은 서버에서 검사한다.
- 원문은 영상을 본 시청자의 페르소나와 브랜드 관심 유도를 요구한다. 실제로 경험하지 않은 운명원 이용 후기는 작성하지 않는다.

**댓글 달기**

- `[댓글 달기]` 클릭 시 채널·영상·본문·중복·일일 상한·프로필을 서버에서 검사한다.
- 기존 `launch_persistent_context`와 지정 프로필 경로를 유지한다. 프로필을 실행하고 한국어 YouTube 댓글 입력창에서 한 글자씩 가시적으로 입력한 뒤 게시한다.
- 게시 후 실제 댓글 표시를 확인한다. 불확실하면 성공으로 처리하거나 자동 재게시하지 않는다.
- 로그인 필요, 댓글 비활성화, CAPTCHA, 브라우저 UI 변경 등으로 작업이 불가능하면 우회하지 않고 실패 사유와 화면 캡처를 기록한다.
- **MCP 프로필과 앱 프로필 비교, 앱 재실행 후 로그인 유지에 대한 별도 검증, 프로필 재사용 구조 변경은 작업 범위가 아니다.** 댓글 게시 과정에서 실제 문제가 발생했을 때만 해당 원인을 조사한다.

**운영 규칙**

- URL 입력 시 영상 ID뿐 아니라 실제 채널 ID를 조회하여 허용 범위를 검증한다. 본인 테스트 영상은 등록된 ID만 예외로 허용한다.
- 영상당 댓글 1개는 프로필을 바꿔도 동일하게 제한한다. 일일 게시 상한은 기본 10개(로컬 날짜 기준)이며 실행 중 중복 작업을 방지한다.
- 이력 삭제는 화면 표시에서 제외하는 처리이며, 중복 방지·일일 상한용 게시 기록 유지. 개별/전체 삭제와 실행 취소 지원.
- 작업 시작부터 종료까지 영상 ID, 프로필 라벨, 댓글 본문, 단계, 결과 시각, 오류, 스크린샷 경로를 기록한다.
- 외부 댓글 게시를 수반하는 실제 E2E는 본인 테스트 영상에서 수행한다.

## 5. UI 기준

최종 디자인은 **HelpNest 스타일의 밝은 SaaS 대시보드**: 좌측 사이드바 / 중앙 영상 목록 / 우측 상세 패널. PDF의 **① 불러오기·② 선택·③ 댓글 달기**를 버튼과 진행 상태로 구분한다.

- 중앙: 채널 5개 필터·최신 영상·직접 URL(가점)·선택 상태.
- 우측: 영상 고민 한 줄·근거/출처·댓글 40~120자 편집·프로필 선택(기본 `유튜브1`)·`댓글 달기`.
- 상태: 프로필 여는 중 → 영상 열기 → 입력 중 → 게시 중 → 댓글 확인 중 → 게시 완료/실패/확인 불가.
- 하단 또는 별도 메뉴: 시간순 이력과 오류 캡처.
- 반응형: 1440px / 1024px / 390px. 상세 수치는 `DESIGN.md`에서 관리한다.
- `dashboard-preview.html`은 모의 시안이며 실제 게시를 수행하는 것으로 표시하지 않는다.

## 6. 최소 데이터·API 설계

| 테이블 | 저장 정보 |
|---|---|
| `videos` | 영상 ID, 채널 ID, 제목, 날짜, 썸네일 |
| `analyses` | 영상 ID, 고민, 근거·출처, 모델, 시각 |
| `comment_drafts` | 영상 ID, 댓글 본문, 수정 시각 |
| `posting_jobs` | 영상 ID(중복 제약), 프로필, 댓글 본문, 상태, 시작·종료 시각 |
| `activity_logs` | 작업 ID, 단계, 결과, 오류, 캡처 경로, 시각 |

| Method | Endpoint | 기능 |
|---|---|---|
| `GET` | `/api/health` | 앱·Ollama 상태 |
| `GET` | `/api/videos` | 지정 채널 최신 목록 |
| `POST` | `/api/videos/resolve` | URL 및 채널 검증(가점) |
| `POST` | `/api/videos/{id}/analyze` | 고민·댓글 생성 |
| `PUT` | `/api/drafts/{id}` | 댓글 수정 |
| `POST` | `/api/posting-jobs` | 검증 후 게시 작업 시작 |
| `GET` | `/api/posting-jobs/{id}` | 상태·오류·검증 결과 |
| `GET` | `/api/activities` | 시간순 이력 |

진행 상태 조회는 짧은 폴링을 사용한다. WebSocket, 작업 큐, 별도 스케줄러는 도입하지 않는다. 실제 구현에 불필요한 테이블·엔드포인트는 만들지 않는다.

## 7. Codex 작업 순서

| 순서 | 구현 | 완료 기준 |
|---:|---|---|
| 1 | 프로젝트 초기화 | Windows에서 Vite·FastAPI·SQLite 기동, Ollama·YouTube 연결 진단 |
| 2 | 영상 목록·선택 | 실채널 5개 조회, 썸네일·제목·날짜·필터·선택 동작 |
| 3 | 영상 분석·초안 | Ollama 출력과 출처 표시, 40~120자 검증, 영상별 차별화 |
| 4 | 서버 게시 제한 | 채널 허용·중복·일일 상한·DB 기록 검증 |
| 5 | Chrome 자동 게시 | 기존 `유튜브1` 프로필 경로로 실행 → 실제 타이핑·게시·확인, 상태·캡처 기록 |
| 6 | E2E·제출 | 본인 테스트 영상에서 3단계 흐름 검증, 2~3분 시연 영상·제작 의도 |
| 7 | 선택 가점 | 프로필 2·3 선택, 직접 URL, 즉석 생성, 후보 영상 탐색을 각각 별도 검증 |

필수 기능을 가점보다 먼저 완성한다. 기존 기능이 정상 동작하면 프로필 관리 구조를 변경하지 않는다. README 실행 절차를 실제로 수행하고 검증되지 않은 기능은 완료 처리하지 않는다.

## 8. 제출 및 평가

| 평가 | 배점 | 증거 |
|---|---:|---|
| 실제 게시 | 25 | 프로필 실행·글자별 입력·게시·댓글 확인 |
| 맥락 이해 | 25 | 실제 영상에서 확인 가능한 장면·발언과 영상별 다른 댓글 |
| 운명원 유도 | 20 | 영상 고민과 연결된 브랜드 언급·관심 유도 |
| 운영 규칙 | 15 | 허용 범위·영상당 1개·하루 최대 10개·이력 |
| 사용성 | 10 | 설명 없이 3단계 작업 사용 |
| 제작 의도 | 5 | 구조 및 구현 선택 이유 |

- **필수 제출:** 2~3분 시연 영상 링크(Drive 전체 공개 또는 YouTube 링크 공유), 제작 의도.
- **선택 제출:** Public Git 저장소. 비밀 키·계정 정보·프로필 데이터·과제 PDF는 Git에서 제외한다.
- 시연에는 본인 테스트 영상의 실제 입력·게시·댓글 확인을 포함한다.
- 기능 완료 여부는 실행·검증 결과로만 판단한다. YouTube 로그인·댓글 정책·UI 상태에 따른 실행 실패를 감추지 않는다.
