최초 Google 로그인 거부는 동일 지정 폴더의 일반 Chrome에서 사용자가 직접 로그인하는 절차로 처리했습니다.
기본 프로필 변경·쿠키 복사·자동화 탐지 우회는 적용하지 않았습니다.
이 영상은 이미 게시 완료 상태이므로 중복 차단을 유지합니다. 새 게시 촬영에는 별도 본인 테스트 영상과 본문 승인이 필요합니다.

## 영상 근거와 초안

초기 검사 영상: `akn-AvCeHBI` · `DvxMfC_KjX0`. 추가 검사: `FBGY7JIM-84` · `DvxMfC_KjX0`.
초기에는 0:33·0:38 화면 문구만 사용했으나, 추가 검사에서 두 영상의 중간·후반까지 각각 8개 화면 자막을 확보했습니다.
공개 스크립트 응답은 `400 FAILED_PRECONDITION`으로 실패해 접근 제한을 우회하지 않고 화면 OCR 경로를 사용했습니다.
2026-10-22부터 초반 4장면 대신 영상 전반에 분산한 8지점 수집으로 변경했습니다.
YouTube의 시각 링크로 재생하고 실제 디코딩 프레임 시각을 확인한 뒤 정지·수집합니다. 재생 실패·시각 불일치 화면은 제외합니다.
표본 수집이며 전체 영상 발언·음성 분석은 아닙니다. 확보 구간 수와 시각 범위를 표시하고, 발언 근거가 없으면 생성·게시를 중단합니다. 채널 소개·홍보 링크를 영상 고민의 근거로 사용하지 않습니다.
이미지 입력 지원 모델은 자막 영역만 판독하고 원본 화면 전체를 근거 이미지로 표시합니다. 텍스트 모델은 Windows OCR을 사용합니다.
전체 이미지 입력의 시간 초과를 확인해 자막 영역 입력으로 줄였고, 실제 13:03 화면의 깨진 OCR을 “나는 그 사람에게 어떤 연인이었을까?”로 판독했습니다.
인식 오류 가능성이 남아 있으므로 게시 전 캡처와 인용문 대조가 필요합니다.
재생성 시 동일 제목·설명, 1분 이상에 분산된 자막 근거 4구간 이상과 실제 캡처 파일이 있으면 재수집을 생략합니다. 이전 초반 수집 형식·3구간 이하·삭제된 캡처는 재사용하지 않습니다.
분석창에서 자막 수집 지점·초안 작성·내용 검토 단계와 경과 시간을 표시합니다. 첫 분석의 공개 자막 미확보 시 영상 재생·이미지 판독 대기는 남아 있습니다.

모델이 실제 출처의 인용문과 영상의 고민을 골라 댓글 전체를 작성합니다. 서버에서 안내 문구를 조합하던 방식은 제거했습니다.
근거 원문의 일치·댓글 길이·금지 표현 검사와 시각·출처 나열형 초안의 거부를 적용합니다.
입력에 없는 기혼 남자·현재 연인 등의 설정을 만든 초안을 발견해, 해당 내용의 모델 검토와 실패 시 재생성·미저장을 추가했습니다.
원문은 근거 영역에 보존하고 댓글에 그대로 복사하도록 강제하지 않습니다. 실제 발언·장면의 뜻을 짚은 시청자 반응인지 모델이 검토합니다.
`[광고]` 자동 삽입과 필수 검사를 제거했습니다. 생성문 전체 40~120자 제한입니다.
핵심 고민의 60자 출력 제한을 180자로 늘리고 완결된 질문으로 작성하도록 변경했습니다. 화면의 줄임·말줄임 처리는 없습니다.
이용 경험·적중·고민 해결 보장은 포함하지 않습니다.
관심 유도 문구의 평가 점수와 의미적 정확성은 자동 검사만으로 보장하지 않습니다.
현재 한국어 음성 전사 도구·Windows 음성 인식기가 없어 whisper.cpp와 다국어 모델 추가 승인을 요청했습니다. 승인 전에는 해당 실행 파일·모델을 설치하지 않았습니다.

## 제작 의도

영상 목록·분석·게시를 세 단계로 구분해 초안의 근거를 확인한 후 사람이 게시 여부를 결정하게 했습니다.
로컬 Ollama를 사용해 별도 AI API 비용을 추가하지 않고, 메타데이터·공개 댓글을 실제 자료로 사용합니다.
구체적 장면이 확인되지 않으면 그 한계를 표시하고 광고 관계와 이용 경험을 꾸미지 않습니다.

운영 규칙은 프런트엔드 버튼 상태와 별개로 FastAPI·SQLite에서 다시 검사합니다.
SQLite 즉시 트랜잭션과 고유 인덱스로 동시 중복을 막고, 제출 전에 시도를 기록해
서버 중단이나 응답 불명확 상황에서 같은 댓글을 다시 게시하지 않도록 했습니다.
요청 범위를 위해 별도 작업 큐·스케줄러·외부 인프라는 도입하지 않았습니다.
