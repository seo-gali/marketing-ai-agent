# 보안 감사

이 앱은 한 사람이 자기 Windows PC에서 영상·광고 초안을 검토하고 지정 Chrome으로 게시하는 도구입니다.
실행 주소는 127.0.0.1입니다. 인터넷 공개 서비스와 로컬 단일 사용자 환경을 나눠 판단했습니다.

## 1. Vulnerability Summary

수정 전 확인한 문제: Critical 0, High 0, Medium 4, Low 2. 조건부 위험: High 1, Medium 1.
범위는 전체 앱 소스·설정·의존성·테스트이며, 실제 계정 공격·쿠키 열람·실게시 부하 공격은 수행하지 않았습니다.
수정 후 확인한 6건 모두 보완·재검증했습니다. 조건부 위험 2건은 아래 P1·P2에 남깁니다.

공격자는 악성 웹페이지 운영자, 로컬 API 호출자, YouTube 제목·설명·댓글 작성자,
잘못 공개 배포한 서버의 원격 이용자로 가정했습니다. 보호 자산은 Google 로그인 상태,
YouTube API 쿼터, 게시 권한, 댓글·작업 이력, DB와 캡처입니다.
신뢰 경계는 브라우저→로컬 API→YouTube/Ollama→SQLite/지정 Chrome입니다.

## 2. Detailed Findings

### S1. 조회·추론 API 요청 제한 없음 — Medium

- 구성 요소: `backend/main.py`, `backend/services.py`.
- 설명: 게시 일일 상한은 조회·초안 생성 호출을 제한하지 않습니다.
- 경로: 로컬 호출자가 영상 목록 또는 분석을 반복 요청 → YouTube 쿼터·로컬 GPU 점유.
- 영향: API 조회 중단·로컬 작업 지연. Ollama는 로컬 모델이므로 $500 AI API 과금 위험과는 다릅니다.
- 권장 수정: 실제 비용이 드는 경로별 요청 상한과 429·Retry-After 응답. 프록시 전달 IP를 무조건 신뢰하지 않기.

### S2. 프레임 삽입 방어 헤더 없음 — Medium

- 구성 요소: HTML 응답·`backend/main.py`.
- 설명: Host/Origin 검사 외에 화면을 다른 페이지 안에 넣는 행위를 차단하는 응답 헤더가 없습니다.
- 경로: 같은 localhost의 다른 포트에서 앱을 iframe으로 표시 → 투명한 버튼을 겹쳐 승인·게시 클릭 유도.
- 영향: 정상 화면에서 원치 않는 조작. 최신 브라우저의 교차 사이트 차단만으로 같은 사이트의 다른 포트를 막지 못합니다.
- 권장 수정: CSP `frame-ancestors 'none'`, X-Frame-Options DENY, nosniff·no-referrer 및 API no-store.
- 확인: 수정 전 실제 `/` 응답에 CSP·X-Frame-Options가 모두 없었습니다.

### S3. 단축 도메인·유니코드로 링크 금지 우회 — Medium

- 구성 요소: `backend/analysis.py:validate_comment`.
- 설명: 기존 검사 TLD 목록에 없는 `bit.ly/test`가 유효 댓글로 통과합니다. 형식 문자를 끼워 넣는 우회도 가능합니다.
- 경로: 광고 문구에 검사에서 빠진 링크를 삽입 → API에 승인 플래그와 제출.
- 영향: 링크 금지 운영 규칙 위반과 악성 사이트 유도.
- 권장 수정: 검사용 유니코드 정규화, 보이지 않는 형식 문자 거부, 도메인 검사를 특정 TLD에 한정하지 않기.
- 확인: 실제 검증 함수가 `bit.ly/test` 포함 문구를 통과시키는 것을 재현했습니다.

### S4. 요청 본문 바이트 상한 없음 — Medium

- 구성 요소: API 요청 수신·JSON 파싱.
- 설명: Pydantic의 문자열 제한은 JSON 파싱 뒤에 적용됩니다.
- 경로: 큰 JSON 또는 chunked 요청 반복 → 필드 검증 전에 메모리·파싱 자원 사용.
- 영향: 응답 지연·메모리 고갈. 공격성 대용량 요청은 실제 계정 환경에 보내지 않았습니다.
- 권장 수정: ASGI 수신 단계에서 Content-Length와 실제 수신 바이트 제한, JSON 형식·연결 출처 검사.

### S5. 이력 전체 차단 목록과 일부 조회 인덱스 누락 — Low

- 구성 요소: `backend/db.py:activities`, 게시 상한·중복 조회.
- 설명: 작업·로그 목록은 LIMIT가 있지만 차단 영상 목록은 전체를 읽습니다. 날짜·본문 검색 전용 인덱스가 없습니다.
- 경로: 장기간 누적 → 2초 폴링마다 누적 목록과 스캔 비용 증가.
- 영향: 로컬 작업 이력의 응답 크기·대기 시간 증가. 대규모 사용자 부하 수치를 추정해 단정하지 않습니다.
- 권장 수정: 이력 페이지 크기·offset 제한, 차단 목록 상한과 선택 영상 상태 조회, 실제 필터에 맞는 인덱스.

### S6. 화면 예외 복구 경계 없음 — Low

- 구성 요소: React 루트.
- 설명: 렌더링 중 예상하지 못한 예외가 발생하면 전체 화면이 사라질 수 있습니다.
- 경로: 예상 밖 응답이나 컴포넌트 예외 → 흰 화면, 복구 안내 없음.
- 영향: 사용자 작업 중단. 브라우저 인증정보 유출을 의미하지 않습니다.
- 권장 수정: 사용자용 오류 경계와 새로고침·초안 복구 안내. 원문 오류·스택은 화면에 표시하지 않기.

### P1. 인터넷 공개 시 인증 없는 게시 API — High, 조건부

- 구성 요소: API 배포 가정, 승인 플래그.
- 설명: `approved=true`는 사람 인증이나 권한 증명이 아닙니다. 현재 앱은 운영체제 사용자와 loopback을 신뢰합니다.
- 경로: 운영자가 인증 없는 역방향 프록시로 앱을 공개 → 외부 호출자가 허용 영상·문구를 넣어 게시 요청.
- 영향: 로그인된 계정의 게시 권한 오용과 이력 노출.
- 권장 수정: 현재는 loopback 전용 실행·외부 공유 금지. 공개 서비스로 바꾸려면 별도 사용자 인증·객체 권한·승인 증명이 필요합니다.
- 상태: 공개 배포·사용자 계정 시스템은 요청 범위에 추가하지 않습니다. 같은 OS 사용자의 악성 프로세스를 앱만으로 격리하지 못합니다.

### P2. 외부 댓글의 프롬프트 주입·의미적 오류 — Medium, 잠재 위험

- 구성 요소: YouTube 자료→Ollama 경계.
- 설명: 출처 ID 존재와 형식 검증은 문장의 사실성·의도를 증명하지 못합니다.
- 경로: 공격자가 설명·인기 댓글에 지시를 삽입 → 모델이 근거와 다른 광고 초안 생성 → 사람이 확인 없이 승인.
- 영향: 허위·부적절한 댓글. 모델에는 파일·브라우저·API 실행 도구가 없어 단독 게시나 키 탈취 경로는 확인되지 않았습니다.
- 권장 수정: 외부 자료는 데이터로 분리, 출처 표시·광고 표시·서버 검사·사람 검토 유지. 임의 악성 문구의 모델 성공률은 미측정입니다.

## 3. Attack Chains

1. 같은 localhost의 악성 페이지 → 프레임 허용 → 사용자 클릭 유도 → 승인된 것처럼 게시. 프레임 차단으로 끊습니다.
2. 요청 제한 부재 → 목록 반복 호출 → 쿼터 고갈 → 정상 조회 중단. 조회 API 상한으로 끊습니다.
3. 외부 댓글 지시 → 모델의 의미적 오류 → 검토 생략 → 부적절한 광고. 출처와 사람 검토가 남는 경계입니다.
4. 인증 없는 공개 프록시 → 이력 조회·승인 플래그 위조 → 로그인 계정으로 작업. 공개 노출을 금지하며, 공개 서비스용 인증을 구현했다고 주장하지 않습니다.

## 4. Secure Design Recommendations

| 문제 | 반영한 수정 | 재검증 |
|---|---|---|
| S1 | 경로별 1분 요청 상한·429·Retry-After, 프록시 IP 신뢰 해제 | 11번째 조회 차단·추가 외부 호출 없음 |
| S2 | CSP·프레임 차단·nosniff·no-referrer·no-store | ASGI 헤더 검사 및 실제 프로덕션 화면 E2E 통과 |
| S3 | NFKC 정규화·도메인/IP·제어/형식 문자 검사 | 단축 주소·전각 주소·보이지 않는 문자 우회 차단 |
| S4 | 파싱 전 수신 바이트 16KB 상한·JSON 형식 검사 | chunked 20KB의 413·비JSON의 415·정상 요청 전달 확인 |
| S5 | 상한 있는 이력 페이지·차단 목록, 선택 영상 상태·조회 인덱스 | 페이지 크기·다음 페이지 중복 없음 확인 |
| S6 | React 오류 경계·복구 안내·새로고침 | 잘못된 응답 픽스처에서 오류 안내 표시 확인 |

Python 전체 검사 19건 통과, 실제 앱 E2E 통과, npm·Python 의존성 감사의 알려진 취약점 0건입니다.
픽스처의 게시 검사는 격리된 로컬 페이지에서만 수행했으며 실제 YouTube 게시를 의미하지 않습니다.

- SQL은 매개변수화되어 있고, React는 문자열을 이스케이프합니다. 임의 명령 실행·파일 업로드·Stripe·메일·비밀번호 재설정·관리자 역할 API는 없습니다.
- API 키는 백엔드 환경 변수에만 있으며, 인증 토큰을 localStorage에 저장하지 않습니다. 초안 자동 저장에는 댓글·필터만 사용하고 만료·삭제 수단을 둡니다.
- SQLite는 WAL과 짧은 연결을 사용합니다. 외부 DB 풀·Redis·CDN은 이 로컬 앱에 새로 도입하지 않습니다.
- `.env`·Chrome 프로필·DB·캡처는 Git에서 제외합니다. DB 백업은 SQLite Backup API로 일관된 복사본을 만듭니다.
- 모델·YouTube 오류, 게시 단계, 요청 차단을 기록하되 키·쿠키·토큰·스택을 클라이언트 응답에 넣지 않습니다.
- 잠금 파일과 고정 런타임 버전을 검사했습니다. 의존성 감사의 CVE 0건은 공급망 전체의 무위험을 보장하지 않습니다.

기준: [OWASP REST 보안](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html),
[SQLite 백업](https://www.sqlite.org/backup.html).

실계정 게시: 본인 테스트 영상에서 승인된 본문 1회 입력·게시·공개 확인 완료.
영상 OCR: 로컬 캡처 경로 제한·고정 스크립트의 인자 배열 실행·원문 인용 대조·본문 승인 경계 유지.
미검증: 공개 배포 침투, OS 계정 분리, 네트워크 프록시 배포, 대규모 부하, 악성 패키지 자체 분석.
