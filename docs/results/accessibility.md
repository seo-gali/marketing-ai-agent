# 접근성·사용성 검수

검수 요청: **“웹접근성을 준수하는지 전체 검수해주세요.”**

범위: 영상 탐색·선택/분석/댓글, 작업 이력, 환경 상태, 404, `docs/index.html`.
WCAG 2.2의 키보드, 포커스, 레이블, 구조, 대비, 상태 알림을 기준으로 코드와 실제 Chrome을 검사합니다.
이 문서는 접근성 인증서가 아닙니다. NVDA·JAWS·VoiceOver 실기기 검증은 하지 않았습니다.

## 구현·검사

| 항목 | 반영 내용 |
|---|---|
| 키보드 | 본문 바로가기, 의미 있는 링크·버튼, Enter/Space, 모바일 메뉴 Escape 닫기 |
| 포커스 | 3px 강조, 메뉴 이동 후 본문, 영상 선택 후 분석 제목, 제출 오류 시 해당 필드·화면 이동 |
| 읽기 구조 | 한국어 lang, 페이지당 h1 하나와 main 하나, 이름 있는 탐색·푸터·분석 영역 |
| 입력 | 보이는 label, URL inputMode, 댓글 오류 aria-invalid/aria-describedby, 화면 문구로 복구 방법 안내 |
| 상태 | 조회·추론·서버 상태를 role=status, 오류를 role=alert로 표시 |
| 이미지·아이콘 | 영상 제목과 중복되는 장식 썸네일 alt="", 장식 SVG aria-hidden, 이미지 폭·높이 예약 |
| 대비·모션 | 주요 텍스트 대비 보완, 포커스 강조, prefers-reduced-motion에서 애니메이션 중단 |
| 모바일 | 1440·1024·390px 및 각 페이지 가로 넘침, 반응형 메뉴·단일 열·줄바꿈 |
| 탐색 | 사용하지 않는 탐색 제거, 클릭 가능한 로고, 실제 경로, 사용자용 404와 복귀 링크 |

`scripts/verify_accessibility.py`는 실제 키보드 메뉴 이동, 본문 바로가기, 포커스 표시,
각 페이지의 접근성 트리·레이블, 주요 텍스트 대비 표본, 모션 제한을 검사합니다.
의도적인 잘못된 응답을 넣어 React 오류 경계의 복구 안내도 별도 픽스처로 검사합니다.

`scripts/verify_e2e.py`는 실제 API 흐름과 모든 앱 페이지의 모바일 넘침·내부 링크·파비콘·메타 설명·현재 저작권 연도를 확인합니다.
완료 결과는 `artifacts/accessibility-result.json`, `artifacts/accessibility-tree.json`, `artifacts/e2e-result.json`에 기록합니다.

## 추가 사용성 요청

- 주요 작업은 파란 버튼으로 표시하고 URL·상세 자료·로그는 더보기로 접었습니다.
- 폼 오류는 blur·제출 시 표시합니다. 입력 중 글자 수는 보여주되 경고 알림을 매 글자마다 읽지 않습니다.
- 댓글은 영상별 localStorage에 임시 저장하고 7일 만료를 적용합니다. 승인 여부·토큰은 저장하지 않습니다.
- 환경 상태에서 이 브라우저의 임시 초안·검색 상태를 삭제할 수 있습니다.
- 검색·필터 유지와 초기화, 초기화 후 Toast 실행 취소를 제공합니다. 빈 검색어는 목록을 반환하지 않습니다.
- 빈 상태에 다음 행동, 성공 메시지·오류 원인·복구 경로, 이력 페이지 이동과 다음 페이지 사전 조회를 제공합니다.
- 외부 게시처럼 되돌릴 수 없는 작업에는 실행 취소를 제공한 것처럼 표시하지 않습니다.
- 숫자 입력·금액·비밀번호·대용량 업로드 기능은 이 앱에 없어 키패드·콤마·비밀번호 토글·업로드 퍼센트를 새로 만들지 않았습니다.
- 목록 썸네일은 API의 120×90 저용량 이미지와 lazy/async 로딩을 사용합니다. 외부 이미지를 서버에 업로드하지 않습니다.

## 남은 검수

2026-10-21 실행 결과: 화면 E2E와 접근성 스크립트 모두 통과.
키보드만으로 본문 이동·모바일 메뉴 열기·이력 이동·Escape 닫기와 포커스를 확인했습니다.
주요 텍스트 대비 표본은 5.62:1·6.27:1·5.46:1이며 모션 제한 설정을 확인했습니다.
앱의 모든 경로와 404, HTML 안내 문서의 링크·390/1440px 넘침 검사도 통과했습니다.
댓글 blur 오류 표시 시 버튼 위치가 바뀌던 문제는 도움말·오류 영역 높이 확보로 수정하고 E2E를 재실행했습니다.
사용자·분석 아이콘과 검색 버튼의 중심 좌표, 푸터 저장소 링크, 모바일 번호 페이지의 1→3→1 이동을 추가 검사했습니다.
번호 이동은 실제 DB를 변경하지 않는 3페이지 응답 픽스처로 검증했습니다.
소개 페이지는 별도 `scripts/verify_docs.py`에서 탭의 방향키·Home·End,
Markdown 팝업의 포커스 순환·Escape 닫기·열기 버튼으로 복귀·모바일 넘침을 검사했습니다.

보조공학 실제 읽기, 사용자 운영체제의 고대비·글꼴 확대, 실제 계정 게시 중 읽기 순서는 미검증입니다.
자동 검사와 접근성 트리만으로 모든 WCAG 성공 기준의 충족을 선언하지 않습니다.

기준: [W3C 키보드 조작](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html),
[W3C 포커스 표시](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html).
